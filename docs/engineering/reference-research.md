### Integration and execution hazards

- Agentic team [agent_system.py](https://github.com/RamyaLakshmiKS/agentic_software_team/blob/e4c1e948f20968714fc96383c1d832d984788380/src/agents/agent_system.py) explicitly uses `permission_mode="bypassPermissions"`, broad `mcp__atlassian__*`, and unpinned `npx -y mcp-remote`. Approval is prompt text rather than separately enforced state. Logs include request/assistant/thinking previews; do not inherit those logging defaults for confidential input.
- Its [workflow evals](https://github.com/RamyaLakshmiKS/agentic_software_team/blob/e4c1e948f20968714fc96383c1d832d984788380/tests/evals/e2e_evals/test_full_workflow.py) include skipped live placeholders. Existing fixtures do not establish a working external workflow.
- PRD Studio [agent.py](https://github.com/addyosmani/adk-product-engineers/blob/3b122eabb86667852132938bc7400740560957d9/python/agents/prd_studio/agent.py) joins model-supplied filenames with an artifacts directory and calls `write_text` without confinement. Absolute/parent paths can escape; default filenames overwrite earlier runs. The stated template validator was not found as a deterministic parser in this source.
- Original assistant [tools.py](https://github.com/khileshwarpriya-design/AI-Product-Manager-Assistant/blob/3eeec544682706f6cd43dd58d7364ebec6415202/tools.py) calls unrestricted `eval(expression)` in a model-accessible calculator. This is arbitrary Python execution under the app's privileges. It was not run.
- Its [langgraph_agent.py](https://github.com/khileshwarpriya-design/AI-Product-Manager-Assistant/blob/3eeec544682706f6cd43dd58d7364ebec6415202/langgraph_agent.py) checkpoints chats to SQLite, but truncates model context to ten messages and hardcodes a Groq model. Reopening project records, complete tool-message pairs and semantic state preservation were not demonstrated.

## Comparative conclusion

Skills-native execution is enough for this engineering assistant's authoring work, but fails the independent-product requirement. Extending an app saves a chat shell while inheriting incompatible permissions and persistence. A small dedicated platform is recommended because its missing components are the product's core domain, not optional features. This is an engineering conclusion from the observed gaps, not a benchmark proving dedicated development is always cheaper.

Use deterministic staged execution, typed outputs, local persistence, approval bound to immutable bytes and independent docs exports. No reference code has been copied. Runtime skill distribution rights remain a design task: existing local development skills are not automatically product assets.
