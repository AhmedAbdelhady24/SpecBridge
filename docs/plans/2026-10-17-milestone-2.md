## Outcome and architecture

An operator can persist goals, stakeholders, decisions, risks, dependencies, API references and conversation notes; classify evidence; search current knowledge/sources without loading histories into a model; deliberately select immutable context snapshots for a run; browse knowledge/artifact revisions; back up and recover an existing workspace. Preserve approved artifacts/reviews/workflow checkpoints and project isolation.

Keep one backend, SQLite and local session authorization. Add an append-only knowledge-version table through transactional schema 1→2 migration. No vector DB, LLM retrieval, new dependency or service. Latest-entry lexical retrieval is bounded by query/result/byte limits with stable ordering and source references. Edits use expected digest; archived entries remain in history but are omitted from active retrieval. Human verification is a separate explicit request with source evidence and note; creation/update cannot self-verify. Knowledge verification never approves an artifact or external action.

Source snapshots preserve the entry ID/version/digest and classification. Sources remain immutable; generation selects explicit IDs, with total context limits unchanged. Compatible-provider messages expose classification; generated user_provided excerpts may cite only user_provided sources, preventing recommendations/assumptions/unknowns/human-verified claims from being silently relabeled. Human verification is a recorded judgment, not automated fact checking. Do not automatically select all knowledge or authorize any tools from it.

## Acceptance and limits

Every source and knowledge reference must be from the target project. Every immutable version remains retrievable after restart; stale writers cannot overwrite. Unknown/assumption/recommendation labels cannot gain verification/publication authority. Retrieval cannot leak other projects or archived current entries; empty query is browsing and nonempty queries rank titles/content deterministically with bounded bytes. Invalid UTF-8/text sizes and limits fail closed. Context selection captures an exact version, never a mutable live reference.

Backup uses SQLite backup API, owner-only new file, integrity and foreign-key checks; destination must not exist. Restore is a separately named CLI operation into a new path, never overwrites live data. Version1 fixtures migrate in one transaction; unknown schema versions are untouched. PostgreSQL remains a future migration path, not claimed implemented. Local-only auth remains required before nonlocal/multi-user use.
